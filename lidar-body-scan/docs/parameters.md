# Parameter reference

Generated by `python -m bodyscan params` from the declarations in the code: every row is an option of the command (`--name VALUE`), a key of a TOML configuration file (`[section]` then `name = value`), and `--set section.name=VALUE`. See docs/tuning.md for how the main parameters change the results.

## bodyscan fuse (turntable)

### [frames]

Reading the frames.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--min-range` | `0.3` m | returns closer than this are ignored |  |
| `--max-range` | `10.0` m | returns farther than this are ignored |  |

### [floor]

Floor detection in the empty scene (defines the floor frame: z up, z = 0 on the floor).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--up` | `(0.0, 0.0, 1.0)` | rough up direction in the sensor frame | (0, 0, 1) for an upright sensor; for a sensor mounted on its side give the sensor axis that points up, e.g. (0, 1, 0) |
| `--max-tilt-deg` | `60.0` deg | largest angle between the floor normal and the up direction | larger: accepts a more tilted sensor, but also walls when close to 90 |
| `--min-sensor-height` | `0.2` m | lowest accepted height of the sensor above the floor |  |
| `--max-sensor-height` | `4.0` m | highest accepted height of the sensor above the floor | excludes the ceiling and far planes |
| `--ransac-threshold` | `0.02` m | RANSAC inlier distance of the plane search |  |
| `--refit-band` | `0.015` m | final least-squares refit on the points within this of the plane |  |

### [platform]

Turntable platform: where it is and how it looks in the empty scene.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--center` | not set | platform centre in the floor frame (X Y) [m]; not set: found from the platform ring in the empty-scene frames | set it when the ring search fails (sensor moved, shiny platform) |
| `--search-start` | not set | where the ring search starts (floor frame) [m]; not set: at the person found in the frames | the ring is searched within --ring-search of this point |
| `--ring-search` | `0.8` m | search distance of the ring around the start |  |
| `--ring-radius` | `0.582` m | radius of the platform ring |  |
| `--platform-top` | `0.03` m | height of the platform top above the floor | z = 0 of the output is here |

### [isolation]

Cutting the person out of every frame (floor frame, platform centre known).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--radius` | `0.9` m | person region: radius around the platform centre | must include the hands: 0.55 cut hands held out sideways (tt16); larger takes in more of the surroundings, which the background removes |
| `--min-height` | `0.05` m | drop points below this height above the floor | lower keeps more of the shoes (platform top at 0.03 m) but may keep platform noise and reflections |
| `--max-height` | `2.3` m | drop points above this height |  |
| `--bg-threshold` | `0.05` m | a pixel is foreground if closer than the empty scene by this | smaller keeps feet and soles closer to the platform, more noise |
| `--bg-relative` | `0.01` | ... or by this fraction of its range, whichever is larger |  |
| `--edge-jump` | `0.05` m | mixed-pixel filter: range jump on both sides of a pixel (0 = off) | removes the ghost points between an edge and the background |
| `--cluster-eps` | `0.06` m | only the largest cluster is kept; DBSCAN distance (0 = off) | smaller may split off hands or feet; larger merges nearby objects |
| `--normal-radius` | `0.05` m | neighbourhood of the per-frame normal estimate |  |
| `--min-columns` | `0.9` | drop a frame that received less than this fraction of its columns (lost UDP packets) |  |
| `--max-person-loss` | `0.1` | drop a frame if more than this fraction of the columns across the person was lost (UDP packets) |  |

### [motion]

Platform angle versus time (any rotation: partial, one lap, several laps).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--turn-deg` | not set | commanded rotation, if known (default: capture.json, else found in the data); used only when the data agree within --loop-tolerance |  |
| `--move-deg` | `360.0` deg | largest single motor command; longer rotations are split into moves of this size with short stops (0 = always one continuous move) | both hypotheses are fitted and the data decide |
| `--sample-seconds` | `0.5` s | spacing of the frames registered for the angles | smaller: more pairs, slower; the spacing grows for long runs anyway |
| `--max-samples` | `320` | at most this many frames are registered for the angles |  |
| `--reg-voxel` | `0.01` m | voxel of the clouds registered for the angles |  |
| `--fine-distance` | `0.02` m | overlap distance of the registration quality |  |
| `--angle-source` | `auto` | where the frame angles come from | auto: mean of the motor model and the model-free solution when they agree, else the model-free one; profile: motor model; free: model-free; pairs: per-pair solve (old) |
| `--model-agreement` | `3.0` deg | auto: the motor model is used only within this rms of the model-free solution (and 3 times this at most) |  |
| `--profile-tolerance` | `15.0` deg | warn if the smoothed pair residual exceeds this |  |
| `--loop-tolerance` | `3.0` deg | the commanded turn is used if the data agree within this |  |
| `--pair-min-deg` | `20.0` deg | shortest turn of a long pair |  |
| `--pair-max-deg` | `60.0` deg | longest turn of a long pair | larger pairs constrain the speed better but overlap less |
| `--max-pairs` | `400` | at most this many long pairs |  |
| `--revisit-pairs` | `60` | pairs per lap one or more laps apart |  |
| `--revisit-window` | `30.0` deg | pairs whose predicted turn is within this of a whole number of laps |  |
| `--boundary-margin` | `0.6` s | consecutive frames within this of every start and stop are registered too (timing of the moves); 0 = off |  |
| `--ignore-phases` | `False` | find the still parts and the turn in the data even if the capture labelled them |  |
| `--huber-deg` | `2.0` deg | outlier scale of the angle solve |  |
| `--correction-spacing` | `2.0` s | free-form correction of the stepper profile: one knot every this many seconds (0 = off) | smaller follows faster speed changes, but noisier |
| `--correction-smoothing` | `3.0` | penalty on the curvature of the free-form correction | larger: smoother correction |

### [views]

Views and the whole-view corrections.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--view-step` | `3.0` deg | one view every this many degrees of turn | smaller: more views (more points per surface patch), slower |
| `--max-views` | `400` | the step grows for long rotations so that at most this many views are used |  |
| `--reference-groups` | `9` | views split into this many groups at random; each view is corrected against the views of the other groups |  |
| `--axis-iterations` | `1` | refinements of the axis position from the view corrections (0 = off) |  |
| `--max-tilt` | `2.0` deg | sway correction bound: tilt |  |
| `--max-turn-correction` | `3.0` deg | sway correction bound: turn |  |
| `--max-shift` | `0.03` m | sway correction bound: shift |  |
| `--max-dropped-views` | `0.25` | views whose correction is out of bounds are dropped if they are at most this fraction of all views (otherwise kept, with a warning) |  |
| `--view-range` | not set | fuse only the views between these angles of the measured turn [deg], e.g. 0 360 for the first lap |  |
| `--angle-iterations` | `0` | passes of a per-view search of the platform angle against the other views (off: the motion model is already better, about 1 deg rms) |  |
| `--angle-search` | `15.0` deg | largest deviation from the motion model searched per view |  |
| `--angle-truncation` | `0.03` m | distance cap of the alignment cost of the angle search |  |

Per-arm correction of every view (A-pose: arms held away from the body).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--limb-iterations` | `2` | passes of the per-arm correction (0 = off) |  |
| `--limb-min-height` | `0.45` m | arms are searched above this height |  |
| `--limb-min-offset` | `0.2` m | a part of a horizontal slice farther than this from the torso axis is an arm |  |
| `--limb-capture` | `0.04` m | view points within this of an arm of the union take its label |  |

### [fusion]

Fusion of the views: support filter, voxel averaging, robust surface fit.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--min-views` | `3` | support filter: a point needs neighbours from this many views (turntable: per lap of views; in place: keyframes) | larger removes more ghosts (and thin parts seen by few views: hands, fingers) |
| `--support-radius` | `0.02` m | neighbourhood of the support filter | smaller keeps thin parts separate (fingers) but rejects more points |
| `--voxel` | `0.005` m | voxel of the fused cloud | smaller: denser output, slower |
| `--confidence-radius` | `0.01` m | neighbourhood of the surface fit and of the per-point confidence | larger: smoother surface, fine details flattened |
| `--surface-fit` | `True` | move every point onto the median surface of the view points around it (off: keep the noisier voxel averages) |  |

## bodyscan smooth

### [smoothing]

Smoothing of an existing mesh (all values are used as given).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--scale-mm` | `12.0` mm | spatial scale (Gaussian sigma) of the filter: every facet averages the facets within twice this distance | sets the size of what is removed. tt11, 4 rounds: 6 mm removes facet noise and small dimples but keeps the scan-row stripes; 12 mm removes the stripes (about 3 cm apart); 16 to 24 mm also flattens clothing folds and the face, and moves the surface 2 to 3 times farther |
| `--rounds` | `4` | number of times the filter is applied | the strength. tt11 at 12 mm, no finishing rounds: 1, 2, 4, 8 rounds move the surface by a median of 0.26, 0.45, 0.74, 1.13 mm (99th percentile 1.8, 2.8, 4.3, 6.4 mm); the stripes fade progressively and are gone at 8 |
| `--finish-rounds` | `2` | rounds at finish_scale_mm after the main rounds (only when finish_scale_mm is smaller than scale_mm; 0 = none) | a wide filter leaves small dimples and, above about 16 mm, fine ripples; 2 rounds at 6 mm remove them (tt11, 24 mm: facet noise p90 5.7 -> 1.6 deg) and move the surface by less than 0.1 mm more |
| `--finish-scale-mm` | `6.0` mm | spatial scale of the finishing rounds |  |
| `--normal-sigma` | `1.5` | bilateral range sigma: how different two facet normals may be and still be averaged (difference of unit normals; 0.35 is about 20 deg, 1.5 is nearly isotropic) | small values keep creases (fingers, chin, folds) but also turn scan defects into sharp creases and leave the surface in flat patches; large values smooth everything alike |
| `--normal-iterations` | `4` | normal filtering passes per round | more passes spread the average farther within one round |
| `--vertex-iterations` | `0` | vertex update passes per round; 0 = automatic: 15 for a median edge of 3.6 mm, times (3.6 mm / edge)^2, times (scale / 12 mm)^2 above 12 mm | too few passes: the vertices do not follow the filtered normals and the surface keeps small dimples |
| `--relax-iterations` | `5` | tangential relaxation passes before the first round (better shaped triangles, the surface does not move) | 0 keeps the input triangles; marching cubes leaves slivers whose normals are noise |
| `--keep-volume` | `True` | offset the surface along its normals to restore the input volume after every round (closed meshes only) | off: the filter shrinks thin parts (arms, fingers) slightly at every round |
| `--max-deviation-mm` | `0.0` mm | keep every vertex within this distance of the input surface (0 = no limit) | a bound on the shape change; it also stops the smoothing where the bumps are taller than the limit (tt11 stripes need 2 to 7 mm) |
| `--smooth-limit` | `True` | with a limit: pull the vertices back with a smooth correction (averaged over about 1.5 edges) before the hard clamp | off: a vertex-by-vertex clamp, which leaves kinks at the edge of the band |

| `--segmentation-min-height` | `0.1` m | ignore points below this height (floor, platform) |  |
| `--segmentation-max-height` | `2.4` m | ignore points above this height (ceiling, lamps) |  |
| `--max-distance` | `8.0` m | ignore points farther than this from the sensor (horizontal) |  |
| `--voxel` | `0.02` m | points are thinned to one per voxel of this size before clustering |  |
| `--cluster-distance` | `0.1` m | points closer than this belong to the same object | larger merges a person with a nearby object; smaller splits arms off |
| `--segmentation-min-points` | `60` | smallest object (thinned points) |  |
| `--wall-min-points` | `3000` | a vertical plane with at least this many points of the static scene is a wall and is removed (objects mode) |  |
| `--wall-distance` | `0.06` m | points within this of a wall are removed |  |
| `--bg-threshold` | `0.1` m | background mode: closer than the empty scene by this |  |

### [tracking]

Following objects across frames.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--track-distance` | `0.5` m | an object is the same as in an earlier frame if its centre moved less than this (horizontal) | larger follows faster walkers, but may swap two nearby objects |
| `--min-frames` | `3` | objects seen in fewer frames are ignored |  |

### [rotation]

Rotation test of every tracked object.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--min-speed` | `0.5` deg/s | slower objects are not rotating |  |
| `--min-turn` | `5.0` deg | pairs that turned less than this do not give an axis |  |
| `--max-axis-spread` | `0.1` m | the axes of the pairs must agree within this (robust spread) | larger accepts noisier rotations, and also some walking people |
| `--max-speed-spread` | `0.35` | the speeds of the pairs must agree within this fraction (robust spread) |  |
| `--min-sign-agreement` | `0.8` | fraction of pairs turning the same way |  |
| `--min-pairs` | `4` | pairs needed for a decision |  |
| `--max-pairs` | `40` | at most this many pairs per object |  |
| `--min-fitness` | `0.5` | pairs whose registration overlap is below this are ignored |  |
| `--registration-voxel` | `0.02` m | voxel of the clouds registered |  |
| `--group-distance` | `0.15` m | rotating objects whose axes are closer than this, turning at the same speed, are parts of one body (an arm split from the torso) | larger also joins two objects on platforms close to each other |
| `--group-speed` | `0.35` | speeds of parts of one body agree within this fraction (same direction) |  |

### [human]

Shape tests of a standing adult (see docs/parameters.md for their effect).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--human-min-height` | `1.2` m | lowest top of a person above the floor | lower accepts children and people sitting, and more furniture |
| `--human-max-height` | `2.3` m | highest top of a person |  |
| `--max-bottom` | `0.5` m | the object must come down to this height at least (feet near the floor) | higher accepts people whose legs are hidden (behind a desk) |
| `--min-width` | `0.12` m | narrowest lateral extent |  |
| `--max-width` | `2.0` m | widest lateral extent (arms spread) |  |
| `--human-min-points` | `80` | fewest points of an object (after thinning) |  |
| `--min-column-fill` | `0.85` | fraction of the 5 cm height slices from bottom to top with points |  |
| `--max-vertical-gap` | `0.3` m | largest height range without points |  |
| `--min-area` | `0.2` m2 | smallest silhouette area seen from the sensor | lower accepts children and partly hidden people, and thin stands, lamps and coat racks |
| `--min-torso-width` | `0.18` m | narrowest solid torso (median run of occupied cells at 50 to 72 % of the height); a torso seen from the side is about 0.25 m deep | lower accepts poles and tripods |
| `--max-flat-fraction` | `0.65` | hard limit: largest fraction of points whose normal lies within flat_angle of one of the 3 dominant directions (panels, cut-outs) | lower rejects more furniture and may reject people seen from far away |
| `--curved-threshold` | `0.45` | flat fraction at which the 'curved surface' feature scores 0.5 (people about 0.2 to 0.35, boxes and chairs 0.5 to 0.8) | lower: furniture scores lower, so do people in stiff clothes |
| `--flat-angle` | `10.0` deg | half angle of a dominant normal direction |  |
| `--score-threshold` | `0.6` | a frame passes when the mean score of the rectangle features reaches this | higher: fewer false detections, more missed people |
| `--min-pass-fraction` | `0.5` | a tracked object is a person when this fraction of its frames pass |  |
| `--min-pass-frames` | `2` | and at least this many frames pass |  |

## bodyscan capture-turntable

### [sensor]

The sensor (or a recording, to test a protocol without the sensor).

| Option | Default | Meaning | Effect of changing it |

| `--source` | `os-122542000054.local` | sensor hostname or IP address, or a .osf/.pcap recording |  |
| `--auto-udp-dest` | `False` | let the SDK set the UDP destination of the sensor (the lab PC needs the stored one) |  |
| `--compress` | `False` | compressed frame files: half the size, but about 0.1 s of CPU per frame, so the writer falls behind and finishes after the capture |  |

### [timing]

Empty scene, countdown, still periods.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--background-seconds` | `3.0` s | empty-scene recording at the start (nobody near the platform or the mark) |  |
| `--delay` | `15.0` s | countdown to take position and pose |  |
| `--hold` | `3.0` s | standing still before and after the turn (motor mode) |  |

### [motor]

Platform driven by this PC over the serial port (omit motor_port to drive it from MATLAB).

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--motor-port` | not set | serial port of the turntable controller, e.g. COM3; not set: the platform is started by girogirotondo_timer.m on the other PC |  |
| `--baudrate` | `9600` | serial speed |  |
| `--motor-boot` | `2.5` s | wait after opening the port (the controller resets) |  |
| `--turn-deg` | not set | turn of the platform (motor mode: default 360, negative turns the other way; two-PC mode: the turn set in MATLAB, stored for the fusion) |  |
| `--max-steps-per-command` | `28800` | longer turns are sent as several commands of at most this many steps (one lap, known to work) |  |
| `--max-rotation-seconds` | `300.0` s | safety stop: a motor command without 'T done' within this ends the capture (one lap takes about 90 s) |  |

### [two_pc]

Platform driven by girogirotondo_timer.m on another PC: length of the recording.

| Option | Default | Meaning | Effect of changing it |
|---|---|---|---|
| `--duration` | not set | record this long; not set: computed from turn_deg and the platform timing below, or until ENTER without turn_deg |  |
| `--platform-delay` | `60.0` s | delay_s of girogirotondo_timer.m |  |
| `--lap-seconds` | `89.75` s | time of one lap of the platform (measured 2026-10-01: 4.01 deg/s) |  |
| `--margin` | `8.0` s | recording kept after the computed end of the rotation |  |
| `--max-record-seconds` | `1800.0` s | safety stop of a recording that waits for ENTER |  |
